## REJECT reason (blocking): false defect empties a healthy table
`destination_schema_defects` treats every `unmapped_fields` entry as a "needed destination column". Unmapped fields are
by definition source fields with NO destination column (the mapper's normal output), so a healthy table
`[id, name, _source_ids]` whose only payload column `name` is fully mapped is reported defective and receives 0 rows
as soon as any unrelated source field (`fax`) is unmapped and carries values.
Tests: test_healthy_table_with_unrelated_unmapped_source_field_is_not_defective, test_healthy_table_with_unmapped_field_still_loads_all_rows
(strict xfail; node-level: 7 rows in, 0 rows written, error + red flag raised). Violates "one broken table, not a pattern" /
no false defect. Fix direction: needed = mapped dest_columns (and unmapped only when the mapper marks a link-bearing field /
`suggested_column`); never raw source field names.
