## Findings
**F1 (REJECT item): guard is not loud at run level.** `src/orchestrator/nodes/resolve_entities.py` ~L282 catches
`isinstance(outcome, Exception)` from gather(return_exceptions=True), appends a string to `errors`, sets
`entity_clusters[entity]=[]` and `continue`s. CandidatePairBudgetExceeded is a RuntimeError, so the run goes on with that
entity un-deduplicated; workflow_manager marks `failed` only if `not target_entities and errors`. So the Fix text
"fail the run loudly if it ever binds" holds at function level only. (Read from code; not executed live.) Fix: re-raise
CandidatePairBudgetExceeded there (orchestrator owner) or mark the run failed.

**F2 (REJECT item): the loss is measured but not surfaced.** `pairs_pruned_by_purging` / `pairs_pruned_by_meta_blocking`
exist only in the local stats dict + logger.debug. resolve_entities_impl's result (L772-774) forwards only
uncompared_pairs, candidate_pairs, blocks_purged. resolution_stats/UI/report see "uncompared_pairs 0" while WNP dropped
e.g. 276,235 of 1.4M edges. The CLAUDE.md honesty-signal problem (a zero that hides drops) is back in a new form. Also
`uncompared_pairs` is hard-wired 0 and the node's "exceeded the comparison budget" warning is now dead text. Fix: forward
the two counts into the result and resolution_stats.

**F3 (accepted-ceiling, but contradicts the stated guarantee): purging coverage is per record, not per pair.**
.tmp/attack3.py: 40 'acme' records (20 true dup pairs sharing only tok:acme), each also in a 2-record ref block.
tok:acme (780 comps) > all smaller (40) -> purged; every member still in another block -> rule satisfied; **0/20 true pairs
found; old code (uncapped) found 20/20**. Purging is a regression below the old cap in this shape. Docstring/commit
claim "every member remains in another block" is true but does not bound pair loss; reword it, and add a unit test
pinning this known loss. `pairs_pruned_by_purging` correctly reports 780 (upper bound).

**F5 (perf/memory):** realistic 6.4k recs 2.2s/313MB, 17.9k recs 8.5s/749MB. Degenerate single block: 3k recs = 4.5M pairs
20s/1.5GB; 6k recs = 18M pairs (under the 20M guard) 88s/5.5GB RSS — the guard's "several GB" is real; a smaller
container OOMs before it binds, and scoring 18M pairs (~25 min at 0.085ms) is the next wall. Guard sized by block
comparisons (bound incl. duplicates), so it can raise on a set whose distinct pairs would fit; loud, so acceptable.
