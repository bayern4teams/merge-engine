## Failed: typo/abbreviation variants that difflib caught are demoted to DISAGREE (not WEAK)
Binary-token cosine gives zero credit to a misspelt token, and the typo'd token (df=1, includes its own record) carries the maximum IDF, so it dominates the norm.
Direct: "Jonh Smith" vs "John Smith" strong -> disagree (cos 0.40); "Acme Grp Ltd" vs "Acme Group Ltd" strong -> disagree (0.58); "J Smith" vs "John Smith" weak -> disagree; "Unseen Foo Co" vs "...Company" weak -> disagree. The docstring's "falls back on exact/strong" is wrong: it demotes.
Level assignment, planted truth (3000 base entities, 1500 true variants, 3000 negatives incl. hard shared-token ones; synthetic, not live):
| corpus | metric | old | new |
|---|---|---|---|
| person | STRONG+ recall / precision | 0.675 / 0.999 | 0.290 / 1.000 |
| person | WEAK+ recall / precision | 0.941 / 0.798 | 0.431 / 1.000 |
| company | STRONG+ recall / precision | 0.458 / 0.997 | 0.373 / 0.969 |
| company | WEAK+ recall / precision | 0.843 / 0.851 | 0.586 / 0.734 |
| address | STRONG+ recall / precision | 0.579 / 0.952 | 0.265 / 0.995 |
| address | WEAK+ recall / precision | 1.000 / 0.763 | 0.397 / 0.990 |
Per-variant STRONG+: person typo_first 0.99 -> 0.03, typo_last 1.00 -> 0.05; company typo_stem 0.95 -> 0.01; address typo_street 1.00 -> 0.11. Gains are real where the report promised them: company drop_form/add_form/stem_only (e.g. drop_form STRONG+ 0.04 -> 0.64) and hard negatives sharing a first name or street (WEAK+ FP 23% -> 0%, 31% -> 0.1%).
Company precision at WEAK+ also falls (0.851 -> 0.734): "Acme" vs "Acme Ltd"-type pairs are promoted when the other token is common, so the hard-negative FP rate rises 0.153 -> 0.222.
End to end (`_resolve_core`, EM refit, name + country + phone with 60% phone agreement, 1000 true pairs, ~2900 hard negatives): person conf>=0.95 recall 0.577 -> 0.260, conf>=0.70 recall 0.845 -> 0.260 (precision 1.0 both, so no precision gain showed up); company conf>=0.70 recall 0.497 -> 0.383.
The 0.90/0.70 cut-offs were calibrated for difflib; reusing them on cosine is not derived from anything (sanctioned standing constants in plan 2.4 are the 0.95/0.70 band, not these).
Mitigation measured (not applied; `src/` is read-only for me): a soft token cosine that credits token pairs matching under the existing `_tokens_match` (exact / prefix / 0.85 difflib), same IDF weights, same cut-offs. Level recall person WEAK+ 0.431 -> 0.677, company WEAK+ 0.586 -> 0.841 (old 0.843), address WEAK+ 0.397 -> 0.798, with person/address precision unchanged-or-better (0.999 / 0.995). End to end: person conf>=0.70 0.260 -> 0.444, company 0.383 -> 0.522 (above old 0.497). Still below old for person (initials and middle names: "J." vs "John" is not prefix-matched at 1 char; "Jonh"/"John" is 0.75 < 0.85). The report defers SoftTFIDF (D-14) but also reports TF-IDF MaxF1 0.79-0.84 vs 0.89 soft [C03]; this recall gap is that gap.
Needed from the lead: either (a) add a fuzzy-token step and a typo test to the acceptance, or (b) a recorded decision that typo-recall loss is accepted for the first cut (then the docstring must say "demotes to disagree"), plus a live measurement.

## Other findings (smaller)
1. `" " in s` routes atomic fields that contain spaces into the token path: phone "+33 1 23 45 67 89" vs "+33123456789" weak -> disagree; vs "...67 98" strong -> weak; timestamps "…14:47:11.62" vs "…:12.62" strong -> disagree. Report Fix 2 says keep atomic fields on the value path; whitespace is a proxy, not a type.
2. `_only_partial_name_evidence` (resolve_entities.py ~1619) still builds its vector without `token_df`; it is consistent with the old levels, not the model's. Only affects the 0.93 ceiling; conservative direction (old levels more generous).
3. "Acme" vs "Acme Ltd" moves disagree -> weak (a single word against multi-word is routed to cosine). Probably desired; it is the source of the company precision drop above.
4. `_TOKEN_RE = [a-z0-9]+` drops accented letters ("José" -> "jos"); same regex as the old `_tokenize`, so no new regression, but IDF over accent-mangled tokens.
