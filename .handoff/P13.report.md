## Changes
- `estimate_model(..., iterations=8, sampled_vectors=None)`: new OPTIONAL last arg = comparison vectors of randomly sampled record pairs.
  When given, after the unchanged EM, each sampled field's `u` is replaced by `_sampled_u`: level frequencies among non-null sampled
  comparisons, with the existing prior pseudo-counts (`_PRIOR_U * _PRIOR_WEIGHT`) so an unseen level floors above 0 (no ZeroDivision/inf/NaN).
  A field with no non-null sampled comparison keeps its EM u. Fields present only in the sample are added; zero blocked pairs still works.
  `None`/omitted: code path unchanged -> byte-identical (acceptance 5/5b pass).
- `m` is EM on blocked candidates, fitted BEFORE u is replaced (choice below).
- `sample_random_pairs(n, k, seed)`: seeded, deterministic, distinct (i<j) index pairs from the full cross product; all pairs if k covers it; [] if n<2.
  Param is `n` (not `n_records`) so the verifier's 2b auto-caller passes an int.
- `SAMPLE_PAIRS = 3000` (named constant, justified in a comment as a sampling-error bound 0.5/sqrt(k) ~ 0.009, not a corpus fit; lead may use it as `k`).
- `#` comment block above `_sampled_u`: do-not-unify, sampled vs df/N, plus `ponytail:` Ceiling (rare value -> floors) and Deferred (calibration; trigger review-band volume).
- Token/value-level exact agreement still uses df/N via the existing `FieldModel.weight`; untouched.

## Choice: m dilution (test 1c note)
Pinning sampled u INSIDE the EM makes every blocked pair (all agree on the blocking field) score as a match, so m dilutes (~0.28). Instead the EM runs
exactly as today (m, match_prior unchanged), then u is swapped. m is therefore identical to current behaviour. Consequence for the lead: scoring now
combines EM-m with sampled-u, so agreement on the blocking field adds large bits to every blocked pair (zip log2(m/u) ~4.5 vs 0.29 bits) - intended by
the report, but thresholds/review band behave differently on live data.
