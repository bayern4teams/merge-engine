# P12 report (worker)

## Changed
- NEW `src/mcp_server/tools/metadata_classification.py`: pure `classify_schema`, `detect_table`, `detect_column`,
  `metadata_columns_by_table`, `OVERRIDE_KEY = "metadata_overrides"`. No module-level mutable state, no numeric constants.
  - Catalog/system tables (DBMS facts): schema in {pg_catalog, information_schema, pg_toast, mysql, performance_schema, sys}
    or `pg_*` schema; name prefix `pg_`, `sqlite_`, `system.`. REMOVED from `schemas[origin]["tables"]` => never analysed,
    mapped, projected or extracted (corpus).
  - ETL metadata columns (name tokens, whole-token match): `etl`/`elt`; `row`+`version`/`rowversion`; a row-lifecycle token
    (created/updated/modified/inserted/loaded/ingested/synced/deleted) plus a stamp token (at/on/ts/time/timestamp/date/dt/by)
    or a DATE/TIME/TIMESTAMP type. Table keeps the column and lists it in `table["metadata_columns"]`.
  - Layers: detected default < per-origin (`origin_config["metadata_overrides"]`) < per-run (`state["metadata_overrides"]`).
    Spec `{treat_as_business, treat_as_metadata, treat_as_catalog, treat_as_data}` (bare, case-insensitive names). Within one
    layer business/data beats metadata/catalog. Column overrides cannot re-admit a removed catalog table.
  - Record: `schema["classification"] = {"tables": [...], "columns": [...]}`, each entry carries detected / effective /
    decided_by (layer) / evidence / risk. Written for every exclusion and every override.
- `src/mcp_server/tools/discover_schema.py`: `discover_schema_impl(origin_config, run_overrides=None)` applies `classify_schema`.
- `src/orchestrator/nodes/discover_schemas.py`: passes `state["metadata_overrides"]` (only when set, so the existing one-arg
  test stub still works); logs counts.
- `src/orchestrator/nodes/map_fields_node.py`: `_build_source_schema_from_discovered` skips `metadata_columns` (refactored
  table selection into `_entity_tables`, behaviour unchanged); unified-record path skips a field that is metadata in every
  discovered table of the entity and business in none (`_metadata_only_fields`); one addition: `ambiguous_splits` from
  `map_fields_impl` are merged into `unmapped_fields[entity]` (a field already unmapped gains `candidates`, otherwise the entry is
  appended, which also makes `has_unmapped_fields` open the review gate).
- `src/orchestrator/nodes/resolve_entities.py`: `_without_metadata` in the sequential prep phase hands matching shallow copies
  without the origin/table's metadata columns; corpus rows (spool, `extracted_data`) untouched. CandidatePairBudgetExceeded
  re-raise and pruned-count stats kept untouched.
