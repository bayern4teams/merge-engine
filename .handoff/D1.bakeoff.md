# D1 bake-off — pre-registered rule (written BEFORE any candidate ran, 2026-11-25)

Defect class (`.handoff/D1.verdict.md`): `idf_soft_similarity`'s cost budget
(`_SOFT_CALLS_PER_TOKEN = 8`) is a count-based cliff — 9 typos in a 20-token
title fall 0.925 → 0.600 (STRONG → DISAGREE) while ≤ 8 never do; and the
constant itself trips the plan-2.4 gates (`test_p14_acceptance::test_6c`
family, red at HEAD since 2f90c83 — I-4 in docs/BENCH_ISSUES.md).

## Candidates (HANDOFF Phase 6b item 3, verbatim shapes)

- **A — r1 as in tree:** budget skip at `_SOFT_CALLS_PER_TOKEN = 8`.
- **B — top-N IDF:** soft-compare only the N highest-IDF unmatched tokens
  (N derived in-code from the pair, never a literal — see gates).
- **C — character-bigram index:** candidate tokens for `token_sim` restricted
  by a shared-bigram (or first-letter+length-bucket) index; typo credit at
  every length, no count switch.
- **F — long-text exact:** fields profiled as long-text skip `token_sim`
  entirely: IDF-weighted exact overlap.

## Rule (from the HANDOFF — pre-registered before any arm ran)

Per dataset ∈ {amazon_google, dblp_scholar, abt_buy, dblp_acm} (+ febrl4 if
fetchable; else UNVERIFIED row):
1. run completes within 3× main's wall time;
2. F1 at the 0.95 bar and recall at 0.70 not below main by > 0.01;
3. over-merged clusters ≤ main + 2;
4. report the full table (precision, recall, F1, over-merged, wall time) per
   candidate;
winner by the rule; ties to the fewest constants.
The three numeric-constant guards may be edited ONLY for a named constant the
user explicitly sanctions; if the classifier denies, stop with [DECISION].
Prefer raising precision (over-merge worse than split).

## Method (in-process, LLM off — same driver as D5)

`.tmp/bench_tools/d1_bakeoff.py`: suite raw data → `resolve_entities.
_resolve_core` with each candidate's `idf_soft_similarity` swapped (the D5
bake-off's monkey-patch harness), scored against the suite truth at the
0.95/0.70 bars; wall clock per arm; over-merged = clusters with a cross-
truth-entity merge (D5 scorer). DBLP-ACM records already cached locally;
others copied from the box `/home/benchmark/suites/merge-engine/<suite>/`
(verified present 2026-11-25). febrl4 fetchability: check, else UNVERIFIED.

Rule application so far (A = baseline = main's in-tree comparator):
- **B_median_df fails rule 1** on amazon_google by 65× wall (14,937 s vs
  229 s — soft-comparing every below-median-DF token pays token_sim per
  token on a 377k-pair candidate pool). Dropped for dblp_scholar re-measure:
  it is 3× larger, so rule 1 cannot flip — deviation recorded here per the
  file's own instruction.
- C_bigram_index is the only arm above baseline F1 anywhere (+0.0008 on
  amazon_google, within noise; recall@0.70 +0.058 there, −0.032 on abt_buy)
  and costs 16×/2.3× wall — rule 1 (3×) fails on amazon_google.
- F_long_exact raises precision (+0.0210/+0.0089) and cuts over-merges
  (−43/−78) at −0.0026/−0.0135 recall — direction matches "prefer raising
  precision", and every F1 dip (−0.0023/−0.0036) and R@0.70 dip (−0.0089/
  −0.0064) is inside the 0.01 tolerance so far. dblp_scholar (A/C/F only)
  decides: any dip > 0.01 there and F fails rule 2 on ALL-datasets.
- Headline across both measured datasets: NO arm changes the picture —
  these product-name suites sit near the floor for ALL four comparators
  (F1 ≤ 0.07). The loss is not the soft-compare budget; the recorded
  mechanisms are the mid-band + I-5 shared-code masking (BENCH_ISSUES).
