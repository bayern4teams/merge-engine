## Defects (strict xfail; fix and the xfail flips to a failure)
1. **A non-answer is remembered as a permanent `keep_separate`** (`test_non_answer_is_not_remembered`, actions `skip`, `""`, `later`, `unsure`). `apply_band_decisions` keeps an unknown action apart in-run (fine) but `_remember` records it, so the pair is never asked again and there is no revocation (Part 3). Fix: record only pairs whose action is in `_MERGE_ACTIONS`/`_KEEP_ACTIONS`.
2. **An abandoned gate records** (`test_abandoned_gate_records_nothing`): `decision` of `abort`/`reject` carrying `pair_decisions` writes them (acceptance item 5: an abandoned or errored gate records nothing). Fix: skip `_remember` unless the feedback decision is approve/edit.
3. (low) A pathologically nested file (`"["*200000`) raises `RecursionError` out of `DecisionMemory.__init__` (only OSError/ValueError caught) and fails the node. Fix: catch `RecursionError` in `_load`.

## Limitations (reported, not blockers)
- Documented Ceiling confirmed: two live instances are last-writer-wins, an interleaved record is lost (`test_two_instances_do_not_lose_each_others_decisions`, xfail). The hook builds a new instance per call, so the window is one resume; re-reading the file inside `record()` would close it.
- Only band pairs are looked up: a remembered `keep_separate` is silently overridden if run 2 scores the same records >= auto_match (xfail `..._survives_a_score_shift_above_the_match_bar`). Design choice; the human's "apart" is not a hard constraint across runs.
- Tables with no primary key get `#ordinal` ids (not stable across runs); content is in the key, so the failure is a safe re-ask, never a wrong apply.
- Cost: one spool read per band pair (cap 50 pending) and one file rewrite per recorded decision; fine at the cap.
