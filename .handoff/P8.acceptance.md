## Judgement calls the lead may contest (relax only the named case)
1. **"exactly the band" vs "the number sent falls".** On this code they cannot both be strict. P15 already made `borderline` = the band, so the old code sends exactly the band when
   it has <= 200 pairs (equal, no fall possible) and the top 200 by score above that. Sending exactly the band therefore cannot send fewer than the old selection; only a
   narrower-than-P15 "uncertain" band could, and the report gives no data-derived width (and the plan forbids inventing one). f2/f3 accept both consistent designs: whole band
   (count rises above 200) or the old budget spent on a non-extreme slice. **No test requires a strict fall.** The report's "drops sharply" refers to the pre-P15 picture
   (selection "from pairs Tier 0 had already decided") and is stale for the same reason P15's "dropped" was; the real defect left is the top-N-by-score truncation (f2).
2. c1 out-of-range (7.3, -0.2, inf) and bool probabilities are treated as "not a probability" (heuristic kept, nothing merged on garbage). If the lead prefers clamping, relax those 4 parametrizations only. NaN is not
   judgement: today `max(0, min(1, nan))` returns 1.0 and a NaN reply becomes a merge (c1 probability_nan, f7).
3. A reply in the legacy shape (`match` + `confidence`, no probability) is "missing the probability field" (c1 `missing_key_legacy_shape`): no fallback to the uncalibrated number.
4. The probability -> score mapping is not specified; only: monotone non-decreasing, p=0.99 >= auto_match, p=0.01 < auto_exclude, output in [0, 1].
