Reproduce: `.venv/bin/python .tmp/p13/sim3.py` (also sim.py, sim2.py, diag.py, edge.py, cost.py in `.tmp/p13/`).

## Passed
- Derived acceptance: 17/17 (`tests/part1/test_p13_acceptance.py`); unit `-k fellegi or match_model` 2 passed. 2.4 grep: 0 hits in fellegi_sunter.py.
- `sample_random_pairs`: n=0/1 -> [], n=2,k>=1 -> [(0,1)], k=0/-1 -> [], k>C(n,2) -> all pairs, always distinct i<j. n up to 1e12, k=3000: 0.1s, 0.7MB (rejection path, no enumeration). md5 of three samples identical under PYTHONHASHSEED 0/1/12345. Float n -> TypeError (fine). Only soft spot: k huge vs n (n=8000,k=1e6) takes 31s/216MB; irrelevant at k=3000.
- Sample-only field: added with prior m + sampled u. Candidate-only field: keeps EM u (inflated, silently - see lead advice). Zero blocked pairs works. Unique-id: `is_unique_id` is never read by `weight`, so sampling does not touch it.
- TF interaction: sampled u overrides only the LEVEL u. `weight("exact", v)` still uses df/N whenever v is in the TF table (4b). Consequence: the sampled u of "exact" matters only when TF misses - e.g. domain fields, where `_comparison_level` returns the registrable domain but TF is keyed on the full normalised URL. So P13's main effect lands on strong/weak/disagree levels, not exact.

## Failed: m/u inconsistency over-scores non-matches (reproduced 5/5 seeds)
Fixture: 700 entities, 30% duplicated with typos/zip change/NULL phone, truth known; candidates blocked on first two name tokens (10-11% true), 3000 sampled pairs.
At p>=0.5 old vs new (same blocked candidates): P 0.95 -> 0.68, 0.93 -> 0.80, 0.83 -> 0.61, 0.98 -> 0.82, 0.97 -> 0.80; FP 8->67, 11->35, 30->89, 3->32, 5->37. AUC 0.9996 -> 0.9985. Mean p 0.15-0.20 vs actual 0.11 (old 0.12-0.14).
Cause: scoring uses sampled (random-pair) u, but `match_prior` is still the EM blocked-population rate (~0.11). The blocking agreement is counted twice (in the prior and in +bits of name exact/strong). Blocked non-matches look like "strong name" (u_strong 0.14 blocked vs 0.0009 random: +0.65 -> +8.0 bits).
Consistent pairing fixes it: same sampled u, `MatchModel(fields, prior = EM match mass / C(n,2))` -> P 0.97-1.00 at 0.5, FP 0-4, mean p 0.09-0.11, recall 0.87-0.94 (derived prior 4.6e-4..6e-4 vs true 3.4e-4). Not in worker scope as specified (report says only "m from EM"), so lead decides; the unmodified spec is what regresses.
Degenerate-EM case (blocking on a field, e.g. zip, or zip-or-name): old and new both collapse (match_prior 0.90, name m_exact 0.04; P = base rate 0.01-0.08) because EM treats "agrees on the blocking key" as the match class. Sampled u does NOT fix that (it improves AUC 0.69-0.73 -> 0.90-0.94 but not precision). This is pre-existing EM, not P13, but P13 does not deliver the report's "m from EM, fine" assumption there.

## Constants (2.4)
- SAMPLE_PAIRS=3000: from the report ("a few thousand"), not corpus-fit; named, grep-clean. The comment's "error bounded by 0.009" is vacuous where it matters: u_true 0.002 -> sd 0.0008 (40% relative), 0.0005 -> 81%. Defensible as a size, the justification text overstates it.
- Floor = `_PRIOR_U*_PRIOR_WEIGHT` (20): pre-existing generic prior, not new, not corpus-fit. With k=3000 an unseen level gets u ~1e-4..9e-4 -> +8..13 bit weights for strong/weak at the floor (name strong +8.0, zip strong +5.5). Large but finite.

## Advice for the lead's `_fit_match_model` call site
1. Draw `idx = sample_random_pairs(len(records), SAMPLE_PAIRS, seed)` over the full `records` list (indices into `records`, NOT candidate_pairs, NOT block members); seed from a stable run value (e.g. entity-type hash via hashlib, not `hash()`).
2. Build vectors with the same `_build_comparison_vector(records[i], records[j], normalise, record_cache)` and pass the SAME `record_cache` as scoring: 3000 pairs cost ~0.05s cached (15us/pair) vs 0.5s uncached, and the projections are reused when scoring.
3. Exclude pairs that are also candidates? Not needed (3000/C(n,2) is tiny); but drop pairs of a record with itself/same _id duplicates.
4. Do not ship without handling the prior: set `match_prior` to EM match mass / C(n,2) when sampled_vectors is used (needs n passed in), or expect precision to drop at current thresholds. Re-run `.tmp/p13/sim3.py` after.
5. A candidate field absent from the sample (all NULL) silently keeps the blocked EM u; log it.
