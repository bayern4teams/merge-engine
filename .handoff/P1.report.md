# P1 report - field-name tokeniser (src/mcp_server/tools/map_fields.py only)

## Changed (one file)
- `_vocab_splits(token, vocabulary)`: fewest-words split(s) of a token into words the vocabulary knows; a segment is
  "known" if its `_stem` equals the `_stem` of a vocabulary word (existing equivalence, so `founding`~`founded`; no new
  word/suffix list). Returns all minimal ties. `ponytail:` comment records the report's Ceiling.
- `_tokenize_field(name, vocabulary=None)`: unchanged when vocabulary is None/empty; otherwise splits a token only when
  exactly one minimal split exists; ambiguous/impossible -> token left whole.
- `_destination_vocabulary(dest_candidates)`: words of destination table + column names (primary + family), runtime-built.
- `_ambiguous_splits(field, vocabulary)`; `map_fields_impl` returns a new top-level `ambiguous_splits` list
  (`{field, reason: "ambiguous split, left unsplit: a|b or c|d", candidates}`) for unmapped fields only. `unmapped_fields`
  reason strings unchanged.
- `_token_overlap` / `_heuristic_match` gained optional `vocabulary` (default None -> old behaviour; schema_matching.py callers unaffected); Phase 2 passes it.
- No numeric constants added, no word lists, no module state, no `.format`, no new columns.
