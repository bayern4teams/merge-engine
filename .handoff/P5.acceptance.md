## Not verified by these tests (attack step / live data)
- Real `staff` run (962k candidates, precision ~0.0002 before): PC/RR on the real corpus need live data and P19's harness.
- CEP `K = sum|b|/2` and CNP `k = sum|b|/(|E1|+|E2|)`: black-box only (2b scaling, token-sharing oracle); which of
  WNP/CEP/CNP is used is the implementation's choice. Attacker: read the diff for the computed constants and for
  literals inside new helpers; check block filtering is either absent (P2 omitted it as a fitted `r`) or ratio-free.
- Real memory ceiling on a multi-million-record corpus (test 5 prints a small-n curve only). Tokenisation of
  punctuation/unicode/numbers is unspecified by the report and not asserted. `_OpaqueKey` cannot catch `re.search`
  over a name or `str(name)`. Test 2b can false-fail a global-top-K (CEP) design that breaks ties asymmetrically; judge, don't force.
- The old `snd:` phonetic rule proposes token-free pairs; test 2 forbids that. If P5 keeps phonetic keys, relax the
  oracle consciously (not silently).
