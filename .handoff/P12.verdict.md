## Business columns (default detection, no override)
- FLAGGED as metadata: created_by, updated_on, created_at, updatedAt, modified_by, deleted_at, synced_at, loaded_at, inserted_at,
  date_created, and (only when type is DATE/TIMESTAMP) last_modified/modified_at.
- NOT flagged: version, batch_size, row_count, load_factor, status, start_date, signup_date, valid_from, hire_date, birth_date.
- What silently leaves MATCHING: only audit-style lifecycle stamps. A business `date_created` (e.g. a founding date) would drop out of
  matching. It stays in the corpus and every exclusion is written to schema["classification"] with risk text; a treat_as_business
  override restores it (verified). Low consequence for matching. The report's own example signup_date is not reproduced (no lifecycle token).
- Weaker spot: the `by` stamp flags created_by / modified_by whatever the type (actor ids; fine for matching).

## Catalog tables
- Caught: pg_catalog.*, information_schema.* (case-insensitive), pg_toast, pg_temp_*, mysql.*, performance_schema.*, sys.*, name prefixes
  pg_/sqlite_/system. (so Mongo system.* collections).
- Not caught: SQL Server dbo.sysobjects, ClickHouse `system` database (schema not in the list; the ClickHouse connector emits no
  schema/full_name, only name). There is no MySQL/SQL Server connector in src/mcp_server/connectors (postgres, mongodb, clickhouse),
  so those entries are untestable live and only matter if a connector is added.
- Over-reach: a user table `public.pg_something` / `pg_orders` is removed from the schema (pg_ is reserved for catalog schemas in
  PostgreSQL, not user table names). Recorded in classification.tables with risk text and logged as a count; `treat_as_data` re-admits
  it (verified, also qualified `pg_catalog.pg_class`). A column override cannot re-admit a removed table (verified). A real user
  schema named `sys` is excluded wholesale; the same override applies.
- Postgres connector already filters pg_catalog/information_schema in SQL, so P12 catalog detection is mostly redundant there.

## Override precedence (probe2)
default < origin < run holds both ways; same layer business beats metadata and data beats catalog; unknown column names are
ignored; case-insensitive; string instead of list accepted; garbage/None specs ignored; qualified "table.col" names are NOT
supported (bare only, as documented). Input schema not mutated. Override on an `id` column to metadata is accepted without a guard
(user error, but no warning).

## Record copies
_without_metadata returns shallow copies; the source rows compare equal afterwards and the copy is a different object; rows with
no `_origin_table` pass through unstripped; matching is case-insensitive on column and table key. Keys cover both name and
full_name (extraction uses full_name). Bare-name key collides if two schemas have the same table name AND a row carries the bare name
(last wins); extraction uses full_name, so not reachable today. Clusters hold record_ids only, so stripped copies do not reach output.

## ambiguous_splits into unmapped_fields
Consumers: human_nodes._build_mapping_rows (uses .get; entry without origin_id/table/confidence yields '' / None / 0.0, ran clean),
has_unmapped_fields (True, gate opens), load_data dropped_fields (counts the field as dropped, correct), workflow_manager
(any(values)), no frontend or API consumer of the key. `candidates` is not surfaced in the gate payload, only in `reason`. No break.
