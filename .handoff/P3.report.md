## Design choices
- Confidence: `verified` iff overlap == 1 (what an IND is), else `probable`. No threshold. Edges: `overlap_ratio` kept.
- Cliff: global per origin, over containment scores of candidates with overlap > 0; no floor sentinel (a 0.0 sentinel made
  a 0.5 junk group beat the 1.0→0.52 gap — found by test at n=200). No gap (one candidate / all equal) keeps all; ties keep the higher group.
- Surrogate `_id` rejected by data: a column whose sampled values EQUAL its own table's resolved single PK is "key-like";
  key-like ⊆ key-like is dropped (kills `ticket.orgid -> org._id`, which equals `ticket._id`, and `alpha._id ⊆ beta._id`).
  The PK itself comes from the existing `_resolve_primary_key` (declared PK, else its pre-existing `_id`/`{table}id`
  fallback) — that name rule is NOT in the three scanned functions and is untouched; discovery strings contain no id/key/nr.
- RHS-uniqueness: saturated column -> `connector.profile_column(mode="FULL")` (distinct == total-null) if available
  (Postgres/ClickHouse); otherwise distinct count == table's max distinct count. Needed because `sample_distinct_values`
  returns distinct values only (no row counts); the acceptance stub has no profile_column (falls to the size rule).
- No heuristic edges when no connector/origin config: a name guess is what P3 removes.

## Ponytail ceilings (as `ponytail:` comments)
Unary INDs only; uniqueness vacuous above sample cap with no profile_column (MongoDB) and in key-less tables; nullable unique
column in a small table not treated unique; shared-key 1:1 FKs dropped by PK⊆PK (declared FK still finds them); one filtered
query per candidate against a saturated parent; FULL scan per saturated column; containment is the only score, so a
low-cardinality column inside a surrogate sequence (score 1.0) survives, a lone junk candidate is kept, and a dirty-data FK just
below the others is cut — remedy is the report's deferred non-name classifier (after Part 3).

# Round 2 (after verdict REJECT)

## Changes (join_graph.py only; analyze_dependencies.py unchanged this round)
1. **Coincidence test** (`_chance`, applied in `_verify_inclusion`): for integer columns the chance containment is the parent's
   density over the child's range; an inclusion that does not exceed it is no edge (`status` 1..3, `is_paid`, `ticket.orgid`
   in dense `org._id`). If chance >= 1 the pair is skipped before any query. Truncated parent: density = profile_column
   distinct_count / sampled span (child range taken as inside the span: sampled extremes understate the true ones); no distinct
   count -> assumed dense. Non-numeric: 0. Ceiling (ponytail comment): a real FK into a dense surrogate sequence is
   indistinguishable from coincidence; declared FKs cover it (probe star: both dense-int true FKs are now missed, 0 false).
2. **Above the cap:** no key-ness or containment from two independent samples. Key = the resolved single PK, or a column
   equal to it only when BOTH samples are complete (exact). Truncated + uniqueness unknown (no profile_column / Mongo) -> admitted
   as parent only if it is the resolved PK. Uniqueness now from `profile_column(FULL)` for any column that survives the
   in-memory prune (also complete-sample columns, fixing the key-less-table misjudgement when profile exists); size rule only as fallback.
3. **Cost pruning** (`_may_include`, before any SQL): complete parent -> samples must intersect; truncated parent -> same value
   kind, overlapping range, and (distinct count known) a binomial test of the sample overlap against the full-containment
   expectation s/D, tolerance 1/pairs (no constant). Probe p3_f (26 tables x 40 cols x 1000 rows, cap 500; naive 439,886 candidates):
   with profile_column: **0 candidates / 0 filtered queries** (was 41,826), 1040 sample queries + 780 FULL profile scans;
   without profile_column (Mongo): **6,084 candidates = 6,084 filtered queries** (26 PK parents x 234 children; 72x below 440k).
   The 780 FULL scans (one per column with a plausible child) are the remaining unmeasured-live cost.
4. Tests: `bag_of_values` now uses a dense `foundedYear` range and asserts NO edge (fails if `_chance` is disabled — checked);
   new TestCoincidence (4), TestAboveTheSampleCap (decoy at 2000 rows, cap 500, with and without profile_column; real FK above
   cap), unknown-uniqueness-needs-PK test; fake connectors get `profile_column=NotImplementedError` (an AsyncMock otherwise
   fabricates stats). 1:1 extension-table loss stays a documented ceiling.
