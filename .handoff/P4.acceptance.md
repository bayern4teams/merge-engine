## Adaptation points / judgement calls (also at the top of the test file)
- Interface is unfixed by the report. `claims()` accepts a role under any key (a key, a sibling string, or a string value labelled
  "junction"/"weak") in analyze_dependencies' output or the `_build_deps_interrupt` payload. If roles live elsewhere, add a source.
- `_Origin` offers `extract`, `profile_column` (exact FULL stats, like Postgres), `discover_*`; it declares NO indexes, so keys must come
  from the data. A fix needing another connector method adds it there.
- 1b (surrogate `_id` + FK pair) is a judgement: the pair is still *a* minimal unique combination. Relax if the lead reads "the minimal key" as `_id`.
- 4: the link is expected on the parent row (`company.industry_id`-style FK found by `get_foreign_keys(primary)`), dimension text on the
  column `name`-like of the sibling; the dimension id may be deterministic (no lookup). `other_primary_tables` (a dimension that is also a
  target entity in the same run, the live case) is NOT tested; the report is silent.
- **Ownership flag:** the find-or-create belongs in `src/mcp_server/tools/load_data.py::_write_child_rows` (it drops "parent references child"
  today), which HANDOFF does not list for P4. The §2.4 grep includes it.
- **P3 interaction (found while building the fixture):** without a `profile_column`-capable connector, P3's uniqueness falls back to "distinct == the
  table's max distinct", so a composite-key junction table's widest column is judged unique and yields spurious INDs (`student.code -> enrolment.student_ref`
  etc.; 14 extra edges here). With an exact `profile_column` the edge set equals truth. Mongo/ClickHouse-without-profile paths stay "unverified".
- Not testable here: live 26-table schema, entities-with-zero-mappings 8 of 16 -> fewer, `industry`/`product_category` non-empty = implemented, unverified.
