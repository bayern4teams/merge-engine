## Defects (strict xfail in the attack file)
1. **A band decision can undo or destroy Match merges.** Triangle A-B 0.80 (band), A-C 0.97, B-C 0.97: rejecting A-B dissolves
   the whole cluster (removed edge counts as 0 in the cohesion cut), so both 0.97 Match pairs end as singletons.
   Violates "Match behaviour unchanged". `test_reject_of_a_band_pair_does_not_destroy_the_match_pairs_around_it`.
2. **A human split in the same feedback is silently re-merged.** `cluster_decisions` split + `pair_decisions` in one
   submission: the manager applies the split, then `rebuild_band_clusters` re-derives from `retained_pairs` and re-unions the
   0.98 pair. `test_human_split_in_same_feedback_is_not_undone_by_the_band_rebuild`. The fix: rebuild must treat existing
   cluster boundaries from human splits as hard constraints (or only touch pairs named by a decision / the committed bar).
3. (minor) NaN score: non-log-odds histogram crashes (`int(nan)`), and a NaN is counted in no band, so counts do not sum to
   the pair count. Not reachable from today's scorers; strict xfail.
4. (minor) Accepted pairs are not persisted: a second resume with different feedback (thresholds only) undoes the first
   merge. Needs a duplicate/late resume to reach.
5. (minor) Pre-P15 checkpoint (no `retained_pairs`): a merge decision is not applied but `band_resolution.accepted=1`
   and pending is cleared (audit claims a merge that did not happen).
Design notes (not defects): a decision for an Exclude-band pair (<0.70) merges it (operator's call, audited);
a decision with no `entity_type` applies to every entity; a committed exclude bar below the run's cannot reach pairs the
run did not retain (documented in `_band_fields`).
