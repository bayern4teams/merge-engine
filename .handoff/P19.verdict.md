## Judgement on K/k labelling
`cep_K`/`cnp_k` are computed on the RAW token blocks (pre-filter, pre-purge). The report's own pipeline diagram puts CEP/CNP after
purge/filter/WNP, and the engine uses neither CEP nor CNP (WNP only). So the names suggest thresholds that are not applied, on a
collection the engine does not use for pruning. Honest only if read as "volume of the raw block collection"; `block_assignments` is the
accurate label. Recommend docstring/report wording say "raw", not a code change. The worker's choice (raw) is defensible and disclosed.
