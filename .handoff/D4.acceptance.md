## Calibration (for attack mode)
* Satisfiable, and discriminating: a throwaway in-process simulation (scratchpad, not src) "token-sorted display name from all person columns" alone passes a1 partly but **fails typo_surname/swap_typo/substituted_given and the repro**, because `cluster_quality._name_groups` links a shared token only when it is >= half of one of the names holding it (a shared given name of 4 of 11 characters links nothing). So a fix that only changes how load_data builds the name will newly flag typo'd surnames (a regression the guards catch). Adding shared-token linking to `_name_groups` made all person tests pass (45 - 3), **but moved the org flags (test c fails)**: the fix must keep the organisation grouping behaviour (c) while letting multi-column person names share a token. That tension is the design question for the worker, not a test bug.
* c8 of the repro fixture (`('jack','moscatt')` vs `(None,'schmick')`: surname substituted AND given name missing, no name token survives) is not recoverable from names. The strict-xfail repro asserts `flagged_count == 0`, so it will XPASS only if the fix also clears c8 (the simulation left c8 flagged -> the repro would stay xfail). a1 tolerates exactly c8; if the worker clears it by a legitimate run-derived rule, fine; if the repro stays xfail the lead must decide whether to relax it (report Verify says "≈ 0").
* Adjacent, not asserted: `_entity_measures` computes `null_identity_share` from one identity column, so the repro fixture reports 4/60 NULL identities (the records missing given_name). Same single-column root; the report does not list it. Attack mode: check it after the fix.
* Untested here (needs live data): febrl4 after flagged ~ 0 of 4,989 and febrl3's real over-merges (1 of 8), plant_febrl4 20/20 on the real run: "implemented, unverified" until `run_bench febrl4|plant_febrl4 after`. Names with a hint-matching non-name column on persons (e.g. a `street_name`) are not covered.
* Constants used (seeds, 160/300/320 cluster counts, the 20 planted) are test-world sizes, not src constants.
