## Findings, ranked
1. HIGH, B-cubed compares a run with itself. `build_reconciliation_report` reads AND overwrites the history on every call, and it is called by the
   final-approval gate preview (workflow_manager.py:745, on each gate fetch) and again by load_data_node (:697, :495, :521). Measured: run1 -> None,
   run2 preview -> 0.889, run2 load report -> 1.0. The report that is written/audited always says "stable". Test: test_rebuilding_the_report_within_one_run_...
   NOTE: the acceptance test test_i_report_carries_the_signals... asserts the 2nd call on the same state == 1.0, i.e. it encodes this behaviour;
   the contract needs "previous = last DIFFERENT run" (key the baseline by run_id, or persist only from load_data_node). Lead decision.
2. HIGH, the flag has a high false-flag rate on healthy data, so `flagged_count` cannot be a P10 invariant as it stands. Threshold = half the mean
   between-cluster dissimilarity (0.36-0.46 in every corpus); within-cluster pairs "Name" vs "Name Limited" / "The Name PLC" are 0.40-0.55.
   Measured false-flag rate on coherent clusters (40 seeds x 60 clusters): real UK company names + legal-suffix variants 14% (Ltd/Limited/PLC/Plc/Inc)
   to 52% (adding Group/Holdings/Corporation); person names with reorder/initials ("Smith, John", "J. Smith") 62-68% at every k; kana with
   株式会社 variants and tickers ("BP"/"BP plc") flagged; random-syllable companies with typos/case/prefix ~8-11%. Accents (folded) and Cyrillic fine.
   Cause is the lexical-only ratio (known P20 ceiling) but also the arbitrary "half": a containment/token-set-aware pair compare would clear these.
   Tests: ..._legal_suffix_variants_..., ..._reordered_and_initialled_... (26/60 and 30/30 flagged today).
3. HIGH, cost is quadratic in the largest cluster, exactly the failure being detected. `name_variation_rate(ns)` runs over all members of every
   multi-record cluster (not distinct names) and materialises all pairs: 400 names 1.5s, 800 5.8s, 1600 22.7s, 5000 distinct names 217s and 943MB RSS,
   per call; and per gate fetch (see 1). Many small clusters are linear (100k records 3.5s). Test: test_cost_of_one_giant_cluster_is_not_quadratic.
4. MEDIUM, miss on a lone giant cluster: with fewer than two named clusters nothing is flagged (documented), so one fused cluster of 5 unrelated names
   (variation rate 0.88) gives flagged_count 0. Fused clusters among >=2 clusters: detected 100% (random pairs of real names, k=3..300).
5. LOW-MED, threshold is a rule, not a corpus-derived scale for the "half". Stable: sd 0.005 over 300-of-600 subsamples, 0.02 at k=20, invariant to
   cluster/record order, no flag flips across subsamples. Instability is only a small-k effect (2 clusters: a split entity "Acme Ltd/Acme Limited" gives
   threshold 0.25 and flags the coherent "Acme Ltd"/"Acme" cluster). Shared generic word ("Holdings") lowers threshold to 0.22 and raises FP 11% -> 14%.
6. LOW, history file: corrupt, empty, list, null, 100k-deep nesting, binary, 5000-digit int, directory-as-path, parent-is-file, unwritable all degrade to
   "not available" with a warning, no crash, no leftover .tmp. Per-entity isolation holds sequentially. Concurrent writers: 8 processes, 2 of 8 entities
   survive (documented last-writer-wins, whole-file not per-entity). A zero-cluster run overwrites the baseline (next run "no records in common").
   A NaN already in a foreign file is written back as NaN. B-cubed is OFF unless `quality_history_path` or MERGE_ENGINE_QUALITY_HISTORY is set.
7. Verified OK: B-cubed equals a brute-force reference on 3000 random partitions with partial overlap (0 mismatches); Hill numbers match closed forms
