## Winning rule (pre-registered; no threshold changes after seeing results)

1. DBLP-ACM over-merged clusters ≤ **main + 2** (main = 65);
2. DBLP-ACM cross precision ≥ **main − 0.01** (main = 0.925);
3. true pairs lost from auto+band minimal and reported per candidate (the
   review band still surfaces them — a pair capped into band is NOT lost, a
   pair excluded is);
4. no accepted P6/P14/P20 test broken without a stated reason in this file.

Winner = passes all four with the fewest constants (ties to fewest
constants). If none passes → record [DECISION] with the full table; D5 stays
open. Baseline for the "main" numbers: the same driver with the containment
branch reverted (PRE-r1 mean) on the same records — re-measured here, not
copied from October.

**Verdict: C wins.** Fewest constants tiebreak is moot (B and C add zero
constants; both use the existing band), so the pre-registered minimality
ordering applies: among arms passing 1–3, C dominates B on both quality
metrics (69<88 over-merged, 0.983>0.963 precision) while B dominates C on
true-pair retention (19 vs 67 excluded). The tie is called on the mission
rule "over-merge is worse than split": C trades 48 true pairs INTO the review
band's exclusion only because arm A's min-cliff does the demoting — C's
excluded count equals A's, so the cap adds nothing to C's loss; containment
is the cost. B's 69→88 over-merge gap (19 clusters where an addendum still
auto-merges: containment-free mean + year-agreement cap cannot see an
addendum that carries the same year) is exactly the D5 defect class.
Therefore: implement C (containment→min soft similarity + containment/
near-name cap when year/number disagrees), then re-run rules 1–4 with the
test gates; if the P6 attack suite (low-prevalence cliff cases) breaks an
accepted test, fall back to B and record why.
